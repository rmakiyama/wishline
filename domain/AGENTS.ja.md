# domain

純粋な Kotlin のモデル。Android も SQL もフレームワークの型も持ち込まない。

Wish は時間をまたいで複数のカードに乗るので、カードのマスは消さない。クローズしたカードが何で作られていたかを残せるのはそのため。

## 不変条件をどこに置くか

判定に何が要るかで決める。

- **エンティティだけで判定できる** — 型で保証する。`BingoCardLayout` は個数が違う場合、重複がある場合、Planned でない Wish が混ざる場合には作れない
- **保存された状態が要る** — リポジトリが確認する。既に開いているカードに乗っているかどうかはこれにあたる。Wish は自分がどのカードに乗っているかを知らないため

同じ規則を両方に置かない。

## リポジトリか queries か

何が返るかで決める。

- **`Wish` か `BingoCard` そのもの** — リポジトリ。id で引くか条件で引くかは問わない。リポジトリは集約のコレクションで、読み取りも含む
- **それ以外の形** — `WishQueries`。`UnassignedWish` は Wish とカードにまたがる事実で、Wish 単体でもカード単体でも答えられない

問い合わせの結果が運ぶのは事実だけで、規則は持たない。削除してよいかは事実を使う側が判断し、書き込む側が強制する。

## 状態

- 排他的な状態は sealed interface で表し、状態ごとに自分のデータを持たせる
- `WishStatus.Done(at)` なら時刻を書き忘れられない。enum と nullable の組み合わせだと両者がずれる余地が残る
